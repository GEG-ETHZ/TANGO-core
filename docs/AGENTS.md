# docs/AGENTS.md

How to write and change a page of the TANGO docs site. Build it with `just docs-build`, preview with `just docs`. The site config is [`../mkdocs.yml`](../mkdocs.yml); this file is excluded from the site.

## Pages

The config-key and output tables under `reference/generated/` are generated from the code by `tools/gen_reference.py` (`just docs-gen`); CI fails when they are stale. To change a description, edit the field's docstring, not the table. A docstring ending in `TODO(docs): drafted, review.` shows as *draft* until a maintainer has checked it and removed the marker.

1. One page answers one question. Intro paragraph, one diagram, a compact table, links to code as repo-relative paths (`src/tango_core/...`).
2. A page states how the code is now, not how it got there. History goes to `archive/` or the commit message.
3. Never copy a fact that has an owner (see the root `AGENTS.md`): link to it. Text that must appear both on GitHub and on the site lives in the README next to the code and is pulled in with a snippet: `--8<-- "src/tango_core/core/README.md"`.
4. A new page is added to `nav:` in `mkdocs.yml`, or it is not on the site.
5. Markdown: fenced blocks carry a language, emphasis uses `*asterisks*`, headings do not skip levels.
6. Lists in prose take the serial (Oxford) comma: "reservoir, wells, and surface plant".

## Diagrams

One system, seen at different depths. Every diagram opens from the same pictogram: the surface plant, the wells and the reservoir around the fluid loop, and the economics to their right, pricing the wells and the plant (`diagrams/system-key.drawio.svg`). The banner (`tools/readme_assets.py`) carries the wordmark and a loop mark in the same colors: surface blue at the top, well purple, reservoir red at the bottom. Economics sits to the right of the three stacked parts in every diagram.

| Kind | Format | Where |
|---|---|---|
| The hero and the three README diagrams (what TANGO models, how you use it, how the code is organized) and the system key | `.drawio.svg`, generated by `tools/diagrams/` (`just diagrams`), editable in draw.io | `diagrams/` |
| Banner | generated SVG, light and dark (`tools/readme_assets.py`, also run by `just diagrams`) | `assets/` |
| Structure and loops | Mermaid in the page | the page itself |
| Live editing in a meeting | `.excalidraw.svg` with *Embed scene* and *Background* on | `diagrams/` |

Rules that keep the set readable as one:

1. Color means a component type, nothing else. Each type has one identity color, used wherever it appears (pictogram, circuit nodes, loop leaves, chips, result tags). Every other block is neutral: white, hairline border, ink text.
2. Solid means in this repository and needs no legend. Dashed means outside it, whether an external simulator, a client that drives TANGO through its command line, or a web app in its own repository. No status words (available, partial, planned) and no roadmap in a diagram.
3. External simulators (CMG, MOOSE, Eclipse, OPM, tNAV; Moskito, OLGA, T2Well; Aspen) are drawn dashed, outside the component boxes, reached through a solid neutral `connector` chip on the box edge: the connector is TANGO's side, an adapter class that implements the component interface and is registered as a variant. RAFT, the group's open-source reservoir simulator, is listed first. The well's `lumped` variant stays in the code but is not drawn.
4. Names are the code's names: `components/well`, `lumped`, `graph (TESPy)`, `SystemBCIteration`. No whiteboard names, no internal codenames, no licensing.
5. No in-diagram title; the page heading names the figure. No legend and no status note: what sits outside the TANGO core box, or is drawn dashed, is not part of TANGO.

Mermaid diagrams use the shared theme so the whole set reads as one system. The first line of every diagram is:

```text
%%{init: {"theme":"base","themeVariables":{"primaryColor":"#FFFFFF","primaryTextColor":"#202124","primaryBorderColor":"#DADCE0","lineColor":"#5F6368","secondaryColor":"#F8F9FA","tertiaryColor":"#F8F9FA","clusterBkg":"#F8F9FA","clusterBorder":"#DADCE0","edgeLabelBackground":"#FFFFFF"},"flowchart":{"curve":"basis","nodeSpacing":40,"rankSpacing":64,"useMaxWidth":true}} }%%
```

| Class | Meaning | Fill | Stroke and text |
|---|---|---|---|
| `well` | wells | `#F3EDF9` | `#7D4FB0` |
| `res` | reservoir | `#FBEAE7` | `#D2402C` |
| `surf` | surface plant | `#E8F0FA` | `#2F6FBF` |
| `econ` | economics | `#E0F2F1` | `#007B83` |
| `code` | any other module or step in this repository | `#FFFFFF` | `#DADCE0`, text `#202124` |
| `err` | an error (runtime diagrams only) | `#FCE8E6` | `#D93025` |
| `out` | outside this repository | `#FFFFFF` | `#9AA0A6`, dashed |
| `human` | where a person writes or decides | `#202124`, white text | `#9AA0A6` |

Each `classDef` also sets `font-size:15px`. A wide diagram is scaled down to the content column, so keep it narrow: prefer top-to-bottom and short labels. At most about twelve nodes.

To change a diagram, edit its script in `tools/diagrams/` and run `just diagrams`; the script is the source, so a hand edit in draw.io (desktop, VS Code extension, or app.diagrams.net) is for a quick look or a one-off and is lost at the next regeneration unless it is carried back into the script. Keep the page background white so it reads in GitHub dark mode, and keep one open change per diagram, since diagrams cannot be merged line by line.

## Ownership and review

Each page states its scope in its first paragraph. Ownership is set per folder in `CODEOWNERS` once owners are named. Owners review their pages when the code they describe changes, and at least once a year.
